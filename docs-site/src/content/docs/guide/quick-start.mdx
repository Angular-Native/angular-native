## Requirements

<Tabs syncKey="platform">
  <TabItem label="iOS · tvOS · visionOS">
    Xcode with the simulator runtime for the platform you want. tvOS and
    visionOS ship theirs separately: `xcodebuild -downloadPlatform tvOS`.

    tvOS, visionOS and watchOS also need a nightly Rust toolchain — their Rust
    targets are tier 3 and ship no prebuilt `std`:

    ```bash
    rustup toolchain install nightly
    rustup component add rust-src --toolchain nightly
    ```
  </TabItem>
  <TabItem label="Android · Wear OS">
    The Android SDK, found through `ANDROID_HOME` or its usual location, plus
    the NDK. There is no Gradle here: `an` drives `aapt2`, `javac`, `d8` and
    `apksigner` itself.

    The Material 3 dependencies are resolved once:

    ```bash
    python3 scripts/fetch-android-deps.py
    python3 scripts/prepare-android-deps.py
    ```
  </TabItem>
  <TabItem label="macOS">
    Xcode's command line tools and nothing else. There is no simulator: the app
    runs on the machine you build it on.
  </TabItem>
</Tabs>

## Install the CLI

<Steps>

1. Put `an` on your PATH:

   ```bash
   npm install -g @angular-native/cli
   ```

   <Aside type="note">
   The package carries the SDK as well as the executable — the shells' Swift and
   Java, the core's Rust, the framework's TypeScript — so there is nothing to
   clone and no `AN_HOME` to set. What it does not carry is a compiled core:
   the platform commands build it with your own `cargo`, and
   [Installing the CLI](/guide/installing/) says what that needs and why.
   </Aside>

2. Create an Angular project, or use one you already have:

   ```bash
   npx @angular/cli@latest new my-app
   cd my-app
   ```

3. Set it up:

   ```bash
   an init
   ```

   This adds a manifest, a native tsconfig, the two framework packages and a
   native entry point. It touches neither `src/main.ts` nor `angular.json`, so
   `ng build` and `ng serve` keep working exactly as before.

4. Add a platform and run it:

   <Tabs syncKey="platform">
     <TabItem label="iOS · tvOS · visionOS">
       ```bash
       an add ios && an ios
       an add tvos && an tvos .
       an add visionos && an visionos .
       ```
     </TabItem>
     <TabItem label="Android · Wear OS">
       ```bash
       an add android && an android
       an wearos .
       ```
     </TabItem>
     <TabItem label="macOS">
       ```bash
       an macos .
       ```
     </TabItem>
   </Tabs>

   <Aside type="tip" title="Why the trailing dot">
   `an ios` and `an android` fall back to the project you are standing in.
   The other five carry a default example from this repository instead, and
   outside the monorepo naming any directory other than the project root is an
   error — so pass `.` and they build yours.
   </Aside>

</Steps>

## Develop with hot refresh

```bash
an dev              # iPhone simulator
an dev --android    # Android emulator
an dev --tvos       # Apple TV simulator
an dev --visionos   # Vision Pro simulator
an dev --watchos    # Apple Watch simulator
an dev --wearos     # Wear OS emulator
an dev --macos      # a window on this Mac
```

`--macos` is the odd one out: there is no simulator, so the app opens on the
machine that is compiling it and the server it talks to is on that same machine.

Saving a component swaps its definition in the running app. You stay on the
same screen, with whatever you had typed and the timers still running.

<Aside type="caution" title="What a save costs when it is not a component">
Editing the framework itself — `packages/platform-native`,
`packages/primitives` or a dependency — cannot be stitched in: only one copy of
Angular fits in the interpreter. The app restarts itself where it stands, comes
back with the new code and loses the component state. Nothing to kill and
nothing to relaunch; you see the change on the next frame.

`packages/runtime/runtime.js` is the one file no reload can carry. The prelude
is compiled into the native binary rather than served in the bundle, so `an dev`
builds the app again and puts it back on the simulator instead of offering a
reload that would change nothing. It takes as long as a normal build, and it is
the only thing that gets a new prelude onto the device.

Rust and the Swift and Java shells are not watched at all: those are `an ios`,
`an macos` and the rest.
</Aside>

## Your first template

```html
<an-view [style.padding]="'16'" [style.gap]="'12'">
  <an-text [fontSize]="28" [fontWeight]="'bold'">Settings</an-text>

  <an-view [style.flexDirection]="'row'" [style.justifyContent]="'space-between'">
    <an-text>Notifications</an-text>
    <an-switch [on]="notify()" (onChange)="notify.set($event)" />
  </an-view>

  <an-button
    [title]="'Save'"
    [variant]="'filled'"
    [accessibilityHint]="'saves without leaving the screen'"
    (press)="save()" />
</an-view>
```

That `an-switch` is a `UISwitch` on iOS and a `MaterialSwitch` on Android.
Layout is flexbox, computed once in the core and handed to every platform as
absolute frames.
